# P3 资源层 —— 精灵/容器格式与解析

> 状态：核心精灵解码在真实游戏图上验证通过(CSprite + CIndexSprite)；同构(Node+浏览器)解析器就绪。

## 已验证格式(对真实客户端文件 hexdump + 渲染双重验证)

### 容器
- **`.spk`/`.ispk`(文件)** = `u16 count` + count 个精灵顺序拼接。
- **`.spki`/`.ispki`** = `u16 count` + `i32[count]` 偏移(指向包内各精灵起始字节)。
  - 验证：`originmark.spki` 偏移 [2,428,832]，offset[0]=2 正好在 `.spk` 的 u16 count 之后。
- 无 `.spki` 时按 count 顺序解码(每精灵解析返回 end 作下一个起点)。

### 精灵编码(小端，RGB565；行内 RLE，offset 为累加间隔，未覆盖处透明)
- **CSprite**(不透明，`.spk`)：`u16 W,H`；每行 `u16 lineLen,u16 segCount`；
  段 `u16 offset,u16 pixCount,u16[pixCount] RGB565`。
- **CIndexSprite**(色键双层，`.ispk` —— 角色/物品)：`u16 W,H`；每行 `u16 lineLen,u16 segCount`；
  段 `u16 offset,u16 ckPixCount,u16[ck] ck像素,u16 pixCount,u16[pix] 像素`。
  ck=可换色层(肤/衣色)，当前按 RGB565 原色绘制。

### 渲染验证(从用户本地客户端原始字节解出)
- `originmark.spk` → 三族徽记(各 11×16)。`out/originmark.png`
- `acslayerman.ispk/00000.ispk` → 斯雷亚男行走动画 12 帧(3 朝向×4，41×79 等)。`out/slayerman.png`

## 地图 .map(已解析验证)

结构(依据客户端 ZoneFileHeader.cpp / MZone.cpp / MSector.cpp):
```
MString ZoneVersion (u32 len + bytes, "=MAP_2000_05_10=")
u16 ZoneID, u16 ZoneGroupID
MString ZoneName
u8 ZoneType, u8 ZoneLevel   (老地图可能 u16，靠描述长度合理性探测)
MString Description
u32 fpTile, u32 fpImageObject
u16 Width, u16 Height
Sector[H*W]: u16 spriteID, u8 property, u8 light   (每格 4 字节)
```
- MString = u32 长度 + 字节。property 位标志见 src/map.js(BLOCK_*/PORTAL/ITEM…)。
- 验证: `adam_c.map` → 256×256=65536 格, 全部有地表 spriteID(范围 [12134..13230]),
  55534 可通行/10002 阻挡。属性热力图 `out/adam_c_heat.png` 清晰呈现等距路网+城镇中心。
- 产物: `src/map.js`(同构解析器), `mapinfo.js`(统计+热力图)。

### 待解: 地表贴图渲染

该注册表藏在客户端加载逻辑/压缩的 FileList.inf 中，是独立的深度逆向任务。
isometric 投影: tile 按 (col,row) 菱形排布(screenX=(c-r)*hw, screenY=(c+r)*hh)。
