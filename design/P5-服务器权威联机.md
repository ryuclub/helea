## 打通过程中的关键发现(逐个攻克)
1. **CG_READY 后断连的真因 = 包序列号校验**。`GamePlayer::processCommand`(GamePlayer.cpp:387)校验
   `packetSequence == m_Sequence`(BYTE, 每包 +1), 不符即 `DisconnectException`(SequenceError.txt)。
   客户端每包都发 seq=0 → CGConnect(0)过、CG_READY(应1却发0)→断。登录链路(loginserver)不校验, 故 CL_* 全 0 也通——误导了所有人。
   **修复**: gameserver 连接用递增序列号(proto.js `resetGameSeq()` + `gframe`)。
2. **in-world 加密是开的(code=28)**, `__USE_ENCRYPTER__` 实际有定义。CG_MOVE 必须按 code 加密
   (SHUFFLE_3 base[X,Y,Dir] + ^code), GC_MOVE_OK/ERROR 按 code 解。GC_SET_POSITION/GC_SAY 是**明文**。
   code = EncryptCode(zoneID,0) = `(((z>>8)^z)^((0+1)<<4))&0xff`; zone12 → 28。
3. **移动语义**: `CGMove(dir, x, y)` 的 x,y 是**客户端当前坐标**(校验 desync), dir 是方向;
   服务器 `nx=x+dirMoveMask[dir].x` 移动, 回 `GCMoveOK(nx,ny,dir)`。dirMoveMask 与客户端 `dirOf` 完全一致。
4. **角色真实区是 zone 12 = eslania_NW**(不是 adam_c=zone72!)。已改渲染 eslania_NW.map + 拷其 tile/obj 块。
5. **addPC 入世后 GQuest 包构建会崩**(全局 GQuest 数据被禁用): `Zone::addPC` 尾部入世信息发送加了真 try/catch
   (Release 下 `__BEGIN_TRY` 空宏不捕获), 玩家已加入 zone 后即使信息发送失败也不断连。

## 客户端实现
- `proto.js`: 递增序列号 gframe; CGConnect/CGReady/CGMove/CGSay 编码; GC_SET_POSITION(341)/GC_MOVE_OK(284)/GC_MOVE_ERROR(283)/GC_SAY(335) 解码。
- `render.js`: 服务器权威移动模式 `setNetMove(fn)` —— 移动意图→回调发 CG_MOVE; `serverStep(nx,ny,dir)` 动画到确认坐标; `serverReject(x,y)` 重同步。
- `index.html`: 登录(loginserver)→LC_RECONNECT→连 gameserver→CGConnect→GC_UPDATE_INFO→CG_READY→setEncryptCode(28)→GC_SET_POSITION 给真实坐标→生成角色+服务器权威移动。多账号 URL `?id=222222`。聊天输入框(CG_SAY/GC_SAY)。

## 已验证
- 单客户端: 登录→入世→服务器权威移动(每步 CG_MOVE→GC_MOVE_OK)→聊天发送(中文UTF-8), 无报错。
- 双客户端(111111/222222)**同时在线**, 各自服务器权威移动。
