## 1. 游戏流程状态机

客户端是一个由 **CLIENT_MODE 枚举** 驱动的状态机。`GameMain.cpp::SetMode()`（`GameMain.cpp:647-1484` 的大型 switch）根据当前 mode 把全局 `g_pUpdate` 指针切到四种 Update 处理器之一，主循环每帧调 `g_pUpdate->Update()`（`GameMain.cpp:2176`）。

### 1.1 四种 Update 处理器（CLIENT_UPDATE，`ClientDef.h:89-95`）

| Update 类型 | 处理器 | 语义 |
| --- | --- | --- |
| `UPDATE_OPENING` | `COpeningUpdate` | 开场动画/初始化 |
| `UPDATE_WAITUI` | `CWaitUIUpdate` | **等待用户 UI 操作**（登录框、选服、选角等交互态） |
| `UPDATE_WAITPACKET` | `CWaitPacketUpdate` | **等待服务器回包**（发了请求在转圈） |
| `UPDATE_GAME` | `CGameUpdate` | 游戏主循环（入世后） |

即所谓「Opening / WaitUI / WaitPacket / Game」四态心跳模型：交互态等用户，等待态等网络，游戏态跑主循环。

### 1.2 完整 24 个模式（`ClientDef.h:58-84`）


### 1.4 关键事实：换图 = 断开并重连 gameserver

这是复刻里**最反直觉、必须照搬**的一条。换地图**不是**本地切 Zone，而是走完整重连流程：

- `GCReconnectLoginHandler::execute()`（`Gpackets/GCReconnectLoginHandler.cpp:29-91`）：
  1. `pClientPlayer->disconnect()` 断开当前 gameserver；
  2. `getSocket()->reconnect(loginServerIP, loginServerPort)` 重连；
  3. 发 `CLReconnectLogin`（带 key）重新认证；
  4. `SetMode(MODE_WAIT_PCLIST)` 重新走「列表 → 选角 → 入世」尾段。
- Zone 实体切换在 `GameMain.cpp::MoveZone(int)`（`GameMain.cpp:2856`），由 `GCUpdateInfoHandler` 在收到新 zone 信息时触发 `MoveZone(getZoneID())`。

> P5 文档已实证：换图链路跑在「服务器权威连接」这条总线上，且 in-world 加密 code 随 zoneID 变化（`code = EncryptCode(zoneID,0)`，zone12 → 28）。**换图复刻 = 重新握手 + 重置加密 code + 重置序列号**，不能省。

## 2. 渲染流程分层

主绘制函数 `MTopView::DrawZone(firstPointX, firstPointY)`（`MTopView.cpp:11636`），每帧把以玩家为中心的可见扇区窗口（宽约 16、高约 25 个 sector）按**严格分层 + 逐行 painter's**画出。

> 深度算法的完整推导见 [`P6-绘制算法-扇区画家与墙透明.md`](./P6-绘制算法-扇区画家与墙透明.md)。本节给绘制顺序总览，不重复推导。

### 2.1 关键前提（来自 P6）

- `MapToPixel(x,y) = (x*48, y*24)`（`MTopView.h:214`，TILE 48×24），逻辑网格是**矩形**不是错排菱形；等距菱形外观来自地砖美术本身。
- 深度顺序 = **按网格行 y（北→南）逐行 painter's**，行内再按 `Viewpoint` / `PixelY` 交错。`m_mapImageObject` 以 `Viewpoint` 为 key 排序（`MTopView.cpp:12853`）。

### 2.2 逐层绘制顺序（DrawZone 内的实际调用序）

| 层 | 内容 | 关键调用 / 证据 |
| --- | --- | --- |
| **① tile 地砖层** | 整片地砖背景，最底层。用 `TileSurface` 缓存 blit，只在滚动越界时重画 | `DrawTileSurface()` `MTopView.cpp:11973`；增量 blit `DrawTilesNoLock` `:12609` |
| **② 阴影层** | 物件阴影 + 生物阴影，整批先画 | `DrawImageObjectShadow` 段 `:12974`；`DrawCreatureShadowAll` 段 `:13091`；`DrawCreatureShadow(&point, ...)` `:13136 / :13207`（玩家阴影） |
| **③ 地面 imageobject + 地面特效** | `Viewpoint==0` 的「地板物件」先吐；随后 `DrawGroundEffect()` | `DrawImageObject` `:12866`；`DrawGroundEffect()` `:12897` |
| **④ 逐行交错主体**（painter's 核心） | 对每个网格行 y：先地面物品 `DrawItem` → 该行 imageObject（`Viewpoint<=y`，墙/建筑） → 该行 creature（`GetY()<=y`，怪/NPC/其他玩家/自己） → 该行 effect | 行循环 `for(y=sY1..sY2)`；`DrawItem` `:13598`；`DrawImageObject` `:13654`；`DrawCreature` `:13697`；玩家单独 `DrawCreature(&point, g_pPlayer)` `:13727`；`DrawEffect` `:13791` |
| **⑤ effect 特效层** | 行内 creature 之后画 sector 特效（魔法/技能/打击特效在生物之上） | `DrawEffect(&point, sector.GetEffectIterator(), sector.GetEffectSize())` `:13791 / :14081` |
| **⑥ 环境层** | 棺木全屏压暗 `DrawAlphaBox`；天气（雨/雪/闪电/昼夜暗度）叠加 | `DrawAlphaBox(&rect,0,0,0,20)` `:12891`；天气见第 3 章「天气/昼夜」 |
| **⑦ UI 层** | 在 zone 之上绘制全部 `C_VS_UI_*` 窗口（背包/技能/聊天/小地图…） | `VS_UI` 框架，见 §2.4 |

> **生物渲染**（④/⑤ 里的 `DrawCreature`）走一条**统一的数据驱动管线**渲染所有生物（人类/吸血鬼/魔灵/怪/NPC/其他玩家），不逐个硬编码 —— 详见 [`P6-生物渲染数据管线.md`](./P6-生物渲染数据管线.md)。`DrawCreature` 本体在 `MTopViewDraw.cpp:519`。

### 2.3 墙透明机制

逐行 painter's 决定了一面墙（高 imageObject，`Viewpoint` 大）会画在玩家之上。原版用**像素级透明/裁剪**让被墙遮挡的玩家仍可见 —— 机制与阈值在 [`P6-绘制算法-扇区画家与墙透明.md`](./P6-绘制算法-扇区画家与墙透明.md) 展开。可见性还受 `ShowInDarkness(x,y)` / `GetDarknessCount()` 控制（`MTopView.cpp:13688 / 13733`），即黑暗范围外的生物不画。
