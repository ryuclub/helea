## "飘着走"根因(已逆向自客户端源码)
旧实现: 按一下键 → col/row 整格瞬移 + 相机瞬跳 + 行走帧固定播 250ms。位移瞬间完成、腿在原地蹬 = 滑步/飘。

原版机制(research/client `MCreature.cpp` InitMoveTable / MTopViewDraw.cpp):
- 一格 = TILE_X 48 × TILE_Y 24 像素; 走一格用 N 帧(N = ACTION_MOVE 动作帧数);
- 每帧推进 `总位移/N` 像素(浮点累积, 末帧补偿舍入), **行走帧与像素位移严格同步**;
- 屏幕位置 = 格子像素 + 格内插值偏移 + **帧偏移 cX/cY**(脚底锚点)。
- 精灵本身**无**偏移字段(只 u16 W,H + 像素行); 偏移在 **CFrame**(SpriteID2+cX2+cY2), 由 MCreatureSpriteTable 索引。

## ✅ 角色动画的权威来源: cfpk 帧包(读客户端源码定位)
**不要猜精灵顺序** —— 客户端绘制注释 `m_CreatureFPK[body][action][direction][frame].GetSpriteID()`
指明映射在帧包 `.cfpk` 里。类型链(framelib/CFrame.h, TArray.h):
```
CFrame                = u16 SpriteID + i16 cX + i16 cY            (6B, cX/cY=脚底锚点偏移)
FRAME_ARRAY           = TArray<CFrame,u16>            → u16 n + n×CFrame
DIRECTION_FRAME_ARRAY = TArray<FRAME_ARRAY,u8>        → u8 nDir + nDir×FRAME_ARRAY
ACTION_FRAME_ARRAY    = TArray<DIRECTION_FRAME_ARRAY,u8> → u8 nAct + nAct×...
CCreatureFramePack    = TArray<ACTION_FRAME_ARRAY,u16>   → u16 nFrameID + nFrameID×...
```
TArray 序列化 = 先写 size(SizeType 字节)再写各元素。解析器: `src/cfpk.js`(已实现, 跑到文件尾精确)。

### acslayerman.cfpk 实测(15 个 FrameID, 各 43 动作)
- **FrameID 0 = 基础身体**; 其余多为武器叠加层/低清占位。每方向序列形如 `a,a,a,b,b,b,c,c,c,d,…`(每姿势保持数帧的**乒乓**)。
- ⚠️ **关键坑(已纠正)**: `acslayerman` 是**进阶职业(ac=advancement class)**, 源码对进阶职业的动作索引经
  `ConvAdvancementSlayerActionFromSlayerAction` **重映射**, 故"裸 ACTION_ 枚举 action1=MOVE"对它**不成立**。
  - action 0–3(各4帧): 站立/瞄准/持枪等**上身**姿势(腿基本不动);
  - action 4–7(各8帧): **腿交替**的走/跑循环。
  - **目视定标(用户确认)**: **STAND=action 3**(自然站立), **MOVE=action 7**(平常走路, 手臂自然、腿交替)。
- 方向枚举(MTypeDef.h, 0–7): LEFT, LEFTDOWN, DOWN, RIGHTDOWN, RIGHT, RIGHTUP, UP, LEFTUP。
- ⚠️ 其他踩过的坑: ①曾只取前 12 帧当 3×4; ②把 chunk0 当 stand+move(实为上身武器动作); ③丢 cX/cY 脚底偏移;
  ④**无头浏览器把"位置滑动"误判成"腿动"** → 教训: 角色动画是否生效必须**真人目视/逐像素 diff 角色区**, 不能只看位移或帧索引变化。
- 精灵源: `acslayerman.ispk` 目录分块包(chunkSize=64), 经 `src/pack.js` 按 spriteID 取。当前仅需块 00064(act3)/00320,00384(act7)。

## ✅ 本次实现(render.js + cfpk.js, 序列+偏移驱动)
- **序列化动画**: 实体存 `anim={stand,move}`(各 dirs[8] of `{s,cx,cy}`, 来自 cfpk FrameID0)。
  动画时钟按真实时间推进序列(FRAME_MS≈45, 与位移**解耦**, 不卡帧); 站立/行走各自循环。
- **每帧 cX/cY 脚底偏移 + 按尺寸缩放**: 贴图左上 = 瓦片左上 +(cx,cy), 单位平面 `scaling=(w,h)` → 脚底精确锚定、不飘不拉伸。
- **8 方向映射** `dirOf(dc,dr)`: 矩形网格(列+=右, 行+=下) → DarkEden 枚举。实测 4 向全对。
- **步进插值**: 空闲取意图(键盘优先, 否则沿寻路路径)→ 一步 stepMs≈320; 进度 p 线性插值瓦片左上, 相机逐帧跟随; p≥1 落格, 意图仍在则接下一步 → 连续平滑走。
- **碰撞**: `_walkable` = 在界内且非 `FLAG_SECTOR_BLOCK_GROUND(0x02)`(MSector.h: 地面不可通过)。
- **鼠标寻路**: `onPointerObservable` POINTERPICK 拾取地面 → 格子 → **BFS**(8 向, 不穿墙角, 节点上限 3 万) → 路径逐格走。
- **出生点修正**: 原 128,128 在中央石台结构内(0x07 全阻挡)→ 改 **103,128**(开阔广场, 周边 81/81 可走); 地形仍以 128,128±40 为中心。
