## 2. 启动方式（可复现）

```bash
cd research/server
# 1) MySQL8 + server 容器（本地 compose）
docker compose -f docker/docker-compose.local.yml up -d
# 2) 容器内编译（dev 镜像已含 cmake）
docker exec odk-server bash -lc 'cd /home/darkeden/vs && make release'
# 3) 用容器就绪配置（已将 docker/conf/*.conf 覆盖 conf/）
# 4) 按序启动三服（gameserver 必须 docker exec -d 正确分离，否则 exec 退出会 SIGKILL）
docker exec -d odk-server bash -c 'cd /home/darkeden/vs && ./bin/loginserver  -f ./conf/loginserver.conf  > login.log  2>&1'
docker exec -d odk-server bash -c 'cd /home/darkeden/vs && ./bin/sharedserver -f ./conf/sharedserver.conf > shared.log 2>&1'
docker exec -d odk-server bash -c 'cd /home/darkeden/vs && ./bin/gameserver   -f ./conf/gameserver.conf   > game.log   2>&1'
```

## 3. 踩坑与解决（按出现顺序）

| # | 问题 | 解决 |
|---|---|---|
| 1 | MySQL 5.7 amd64 在 qemu 下段错误(15 次崩溃) | 改用 **MySQL 8 arm64 原生镜像**（README 称 5.7/8 均测过）；5.7 dump 在 8 上零致命错误灌入。见 `docker/docker-compose.local.yml` |
| 2 | dev 镜像缺 cmake，`make` 失败 | 容器内 apt 装 cmake；并补进 `Dockerfile.dev` |
| 3 | 仓库 `conf/` 指向开发者私网(192.168.0.16) | 用容器就绪的 `docker/conf/*.conf`(odk-mysql/127.0.0.1) 覆盖 `conf/`（原文件备份 `.devbak`） |
| 4 | gameserver 加载期崩溃(物品类别/路点) | 见下「源码加固补丁」 |
| 5 | setsid 后台进程被 docker exec 会话回收 SIGKILL，误判为崩溃 | 改用 `docker exec -d` 正确分离 |

## 4. 源码加固补丁（本地研究，均为防御性）

根因：本 DB 种子数据 + 此 opendarkeden 构建存在**加载顺序缺陷**——多个任务/路点加载器排在 `ZoneInfoManager::load()`(ObjectManager.cpp:767) **之前**，却要按 zoneid 取活动 Zone；区域未加载 → 异常 → 因 `__BEGIN_TRY/__END_CATCH` 是空宏(Exception.h:107)、`Assert` 在 Release 被编译掉、且 `set_terminate` 直接 abort，故整服崩溃。

| 文件 | 改动 | 目的 |
|---|---|---|
| `src/server/gameserver/Treasure.cpp` (getItemClassFromString) | 未知/空 class 不抛异常，返回 `ITEM_CLASS_MAX` | 修加载期物品类别崩溃 |
| `src/server/gameserver/ItemFactoryManager.cpp` (createItem) | 非法 class catch 后 `return NULL`（原 fall-through 越界） | 修运行期越界 |
| `src/server/gameserver/GQuestTouchWayPointElement.cpp` | 先查区域、判空再建 MonsterCorpse | 区域缺失时跳过路点 |
| `src/server/ZoneUtil.cpp` + `src/server/gameserver/ZoneUtil.cpp` (getZoneByZoneID) | 区域/区域组缺失返回 NULL，不抛 Error | 消除加载期 throw→terminate |
| `src/server/gameserver/GQuestInfo.cpp` (GQuestInfoManager::load) | 早返回跳过（XML 已空，全局任务非核心） | P1 引导 |
| `src/server/gameserver/GQuestCheckPoint.cpp` (load) | 早返回跳过（区域未加载时建路点必崩） | P1 引导 |

数据侧：`data/SimpleGQuest.xml`、`data/EventGQuest.xml` 临时清空（备份 `.orig`）。

> ⚠️ 这些是「让服务端先跑起来」的引导补丁，非最终方案。**正解是修正 ObjectManager 加载顺序**（先 ZoneInfo/ZoneGroup 再任务/路点），届时可恢复全局任务与事件路点。列为后续任务。
